# 데이터 검증과 안전한 공시 갱신

기준: 2026-10-21 KST. 이 문서는 코드와 로컬 테스트로 확인한 내용을 기록한다. 공식 홈페이지 접근 성공이나 스키마 통과만으로 금액의 사실성을 증명했다고 주장하지 않는다.

## 감사에서 확인한 사항

- 기존 정적 HTML/JavaScript, Playwright 수집기, 파서, 후보 선택기를 유지했다. 수집기·파서·`lib/candidate`를 새 기술로 교체하지 않았다.
- 기존 `validateAll`은 수집 결과를 항공사 코드 대신 배열 인덱스로 연결했다. 누락·순서 변경 시 다른 항공사의 수집 상태가 사용될 수 있었다.
- 기존 검증기는 `usedMock`을 검사하지 않았다. 실수집 이후 API 실패/미설정으로 mock 파서가 반환되어도 출처가 `live`이면 게시 가능한 경로가 있었다.
- 누락 통화를 KRW로 가정했고, 부분 파싱 실패와 50% 이상 급변이 있어도 통과 구간만 게시할 수 있었다. 원문 링크, 적용월, 날짜, 중복 구간 검사는 충분하지 않았다.
- 기존 `--dry-run`도 `public/data/pipeline_log.json`을 수정했다. mock 실행은 forecast 입력까지 저장할 수 있었다.
- `lib/market`는 환율만 실측 가능하고 석유·스프레드 등은 mock 상수를 반환한다. `source: live`도 실측 환율과 mock 석유 입력의 조합이었다. 이번 공식 공시 파이프라인은 forecast 파일·생성 시각을 수정하지 않는다.
- KST 월 계산은 +9시간 이동 후 로컬 getter를 사용했다. 호스트가 KST이면 월말에 시간대를 두 번 적용할 수 있었다. UTC getter로 수정했다.
- 공식 피드 자체는 51개 구간을 보유하지만 KE/OZ 등 다수는 2026.04 과거 데이터다. 최신 표시 데이터는 `_shared.js`의 공시·월별 override와 페이지 계산 배열에서도 온다. 피드 날짜를 최신 월로 바꾸거나 기존 값을 갱신하지 않았다.
- TW 과거 공시의 `current: null`에는 원문 `-`라는 설명이 있다. 오류나 0원으로 재분류하지 않았다. BX 2026.05 수동 override는 공식 확인 상태 필드가 없는 기존 데이터로 경고한다.

## 파일과 동작

| 파일 | 역할 |
| --- | --- |
| `lib/validation/records.js` | 하위 호환 정규화, 필드·날짜·통화·상태·중복·URL 검증, 선택적 연결 검사 |
| `lib/validation/index.js` | 파싱/수집 후보 검증, mock·수집 실패·급변·0원·부분 공시 게시 차단 |
| `scripts/run_pipeline.js` | 수집 → 파싱 → 후보 검증 → 최종 파일 검증 → 백업/원자적 교체 |
| `scripts/validate_data.js` | 로컬/CI 공식 JSON 검증; Git 기준점과 바뀐 항목 엄격 검사 |
| `scripts/validate_service_data.cjs` | 실제 서비스의 수동 JSON과 `_shared.js` 11월 공식 공시 선언 검사 |
| `.github/workflows/data-validation.yml` | Node 22에서 기존 의존성 설치, 전체 native test, 기존 및 변경 데이터 검사 |
| `tests/data-validation.test.cjs`, `tests/pipeline-safety.test.cjs` | 데이터 검증/게시 보존 회귀 테스트 |

기존 `items.current`, `currency`, `distanceRange`, `currentPeriod` 계약을 보존한다. 통과한 신규 항목에만 `metadata`를 추가한다. 정규화는 항공사, 출발/도착지, 출발국, 부과 기준, 통화, 편도 금액, 적용월, 발표일, 적용 시작/종료일, 수집 시각, 출처 URL, 데이터 상태, 검증 상태/시각, 명시된 방향, 원문 검증 상태/시각을 구분한다.

정보가 없으면 `null`이다. 적용월만으로 1일/말일을 만들지 않으며, 원문 확인일을 발표일·수집일로 대체하지 않는다. `direction`은 명시된 값 또는 `oneWay: true`에서만 얻는다. 기술 검증 `validationStatus: passed`는 원문을 사람이 검증했다는 뜻이 아니므로 `sourceVerificationStatus/sourceVerifiedAt`와 구분한다.

## 게시를 중단하는 조건

- JSON 구조/필수값 오류, 음수·비수치·무한대, 통화 미상/불일치
- 적용월 미상/불일치/과거로 후퇴, 다음 달 이후의 신규 공시, 유효하지 않은 날짜
- 공식 HTTPS 호스트 이외 출처, 수집/파싱 출처 불일치, 사용자정보가 포함된 URL
- 같은 항공사·월·구간·통화 중복, 기존 대비 구간 수 감소 또는 일부 거부된 구간
- 전망/미확인 데이터 혼합, 명시된 왕복·귀국편 금액
- mock 파서/collector fallback/수집 오류/누락된 수집 결과
- 같은 통화와 부과 기준의 이전 데이터 대비 50% 이상 변화, 신규 0원, 통화별 검토 상한 초과

급변·상한·0원은 거짓이라는 판정이 아니라 검토 보류 조건이다. 원문 대조 전에는 전체 실행 배치를 게시하지 않는다. 기존 공시는 보존한다. 자동 우회 플래그는 제공하지 않는다. 실제 공식 급변·0원은 근거를 보관한 별도 데이터 변경 리뷰가 필요하다.

공식 호스트는 기존 수집 대상과 서비스에 기록된 원문 도메인 목록으로 제한한다. TW는 기존 twayair.com과 저장된 11월 공시 URL의 trinityairways.com을 모두 허용한다. 허용 도메인이 바뀌면 목록을 코드 리뷰로 갱신해야 한다.

## 실행과 로그

```sh
node --test tests/data-validation.test.cjs tests/pipeline-safety.test.cjs
node scripts/validate_data.js
node scripts/validate_data.js --base-ref HEAD
node scripts/validate_service_data.cjs --base-ref HEAD
node scripts/run_pipeline.js --mock --dry-run --only LJ
```

mock dry-run은 거부된 후보를 실제 운영 검증기에 넣기 때문에 종료 코드 **1이 정상적인 검증 결과**다. 통과한 실제 후보만 종료 코드 0이다. `--mock` 또는 `--skip-llm`에 `--dry-run`이 없으면 수집/게시 전에 차단한다. dry/mock/skip 실행은 공개 데이터와 로그 파일을 수정하지 않는다.

실제 게시 시 `artifacts/data-validation/`에 실행별 오류/경고 JSON과 수정 전 `.backup.json`을 보관한다. 해당 디렉터리는 공개 서비스 경로 밖이다. 파일 교체 직전에 원본이 바뀌었는지 확인하고 같은 디렉터리에 임시 파일을 만든 뒤 rename한다. 교체에 실패하면 기존 파일과 백업을 보존하며 실행은 실패한다. 변경이 전혀 없으면 공개 피드의 최신 시각도 갱신하지 않는다.

`node scripts/validate_data.js --check-links` 또는 실제 파이프라인의 `--check-links`는 선택적 실연결 검사다. HTTPS, 허용 호스트, 제한된 redirect 횟수, timeout을 적용한다. 잘못된 redirect, 인증/차단 응답, timeout은 실패로 보고한다. 연결 검사는 원문 금액과 파싱값 일치 검사와 별개다. CI는 불안정한 항공사 네트워크에 의존하지 않는 호스트/형식 검사만 실행한다.

## 실제 서비스 데이터 검사 범위

`validate_service_data.cjs`는 `_shared.js` 전체 실행 대신 독립된 `NOVEMBER_2026_OFFICIAL_NOTICES` 선언 블록만 네트워크·DOM이 없는 VM에서 읽는다. 항공사 중복, 통화·금액, 구간 수, 발권 기간, 방향/출발국, URL, 발표/검증 날짜, 노선군 형식/중복을 검사한다. TW의 원문 대시는 `null`로 남긴다. 코드 선언 구조가 변경되어 블록을 찾지 못하면 CI가 실패한다.

추가로 `public/notice-group-source.js`의 10월 공식 노선군 선언을 별도 VM에서 읽는다. 항공사·공식 URL·원문 확인 상태/시각·통화·편도/출발국·발권 적용일·구간/금액 배열을 검사하고, 같은 항공사/부과 구간의 11월 선언에 포함된 10월 비교 금액과 대조한다. 배열 순서가 바뀌어도 구간 문자열로 연결하며, 새 공시 파일이 빠지거나 값이 어긋나면 CI가 실패한다. 공시 발표일 미제공은 확인일로 채우지 않는다.

현재 검사 결과: 11월 공시 선언 8개사, 10·11월 숫자 100개; 별도 10월 노선군 선언 BX 1개사·4금액을 4구간 모두 대조; 수동 JSON 18개 항공사/월, 숫자 107개. 11월 선언은 경고 4개, 별도 10월 선언은 발표일/수집시각 미제공 경고 2개, 수동 JSON은 경고 319개다. 경고 대부분은 과거 필드에 발표일·수집일·적용일이 없는 경우이며 숫자를 임의 보완하지 않는다. 기준 피드 51개 구간은 오류 0개, 기존 메타데이터 경고 111개다.

이 검사는 비동기 조합 이후의 최종 `window.MANUAL_OVERRIDES`, 모든 홈페이지/계산기 요약 배열, 공식 원문의 금액이 완전히 일치한다는 증명이 아니다. 특히 11월 공시 URL을 10월 값의 원문으로 재사용해 검증했다고 간주하지 않는다. 해당 부분은 별도 브라우저 회귀 검사 및 원문 대조가 필요하다. 페이지에 새로운 월별 공시 객체를 추가할 때 이 어댑터도 확장해야 한다.

## 검증 결과와 남은 운영 확인

- 데이터 검증 native test 43개 통과: 금액/통화/월/날짜/출처/모의값/전망/중복/RT 차단, 값 누락 보존, KST 경계, 실제 서비스 선언 검사, 별도 10월 노선군 출처 및 월간 대조 검사 포함.
- 최종 통합 59개(데이터 43+게시 안전성 6+계산기 10)가 전부 통과했다. 모의 게시와 실제 mock dry-run 모두 공개 데이터 보존을 확인했다.
- 정상 후보를 임시 디렉터리에 게시하고 원본 백업·신규 metadata·forecast 보존을 검사했다. sandbox의 rename 제한으로 최초 1개가 EPERM이었으나 중앙 샌드박스 외 실행에서 통과했다. 운영 데이터에는 쓰지 않았다.
- 실제 mock dry-run의 종료 코드 1과 모든 `public/data/*.json` 해시 불변을 검사했다.
- 공식 사이트 실연결, 실제 API 파싱, 프로덕션 게시, 외부 CI 실행 결과는 이 문서의 로컬 검증 범위 밖이다. 운영 수집은 실행하지 않았다.
- 전용 JSON schema 패키지나 테스트 프레임워크, 데이터베이스, 유료 서비스는 추가하지 않았다. Node 내장 test/VM/fs와 기존 의존성을 사용한다. 실패 로그/백업의 보존 기간은 운영자가 결정해야 하며 자동 삭제는 구현하지 않았다.
