# 최신 렌더러의 원문 검증 범위 표시 검토

검토 시각: 2026-10-21 19:04 KST. 로컬 소스·Node VM 실행 결과이며 운영 배포 확인은 아니다.

## 확인한 실행 순서와 수정

- 메인은 `_shared.js` → `home-sep20.js` → `home-platform.js`, 계산기는 `_shared.js` → `calculator-oct20.js` → `calculator-platform.js` 순서다. `source-provenance.js`는 `_shared.js` 앞에서 로드한다.
- 두 렌더러의 오래된 기본 객체에는 9개사, YP 11월 확정, 대한항공 일부 인하 등의 문장이 남아 있었지만, 현재 실행에서는 표시 전 `NOVEMBER_2026_NOTICE_COPY`로 덮어쓴다. 기본 객체의 검색 결과만으로 현재 화면 오류로 보고하지 않았다.
- 실제 최종 설치 값에 남아 있던 10월 전체 공식값처럼 보이는 표 제목과 검증 대기를 미발표로 표시하는 문구를 수정했다. 10월 보관 기록의 검증 상태는 결과별로 구분하고, 검증 대기와 공시 미발표를 구분한다.
- 계산기 공식 링크의 확인 표시는 금액 배열 존재가 아닌 `NOVEMBER_2026_SOURCE_REVIEW.verified`를 사용한다. 검증되지 않은 11월 원문 링크가 존재해도 링크를 10월 공지로 잘못 설명하지 않는다.
- 메인 Twitter 설명과 계산기의 WebApplication JSON-LD도 최종 요약과 일치하도록 갱신한다. FAQ는 같은 검증 범위 설명을 사용한다.
- 공시 금액, 노선 구간, 환율, 계산 코어는 수정하지 않았다.

## 실행 증거

`node --test tests/renderer-source-copy.test.cjs`: 3개 테스트 통과.

1. 실제 두 스크립트를 VM에서 실행해 6개 언어의 최종 요약·메타데이터가 원문 대조 집계를 사용하는지 검사했다.
2. LJ 금액을 테스트 입력에서만 변경하면 검증 집계가 8 → 7로 줄고 링크가 검증 대기로 표시되는 것을 검사했다.
3. 10월 보관 기록 범위, 검증 대기와 미발표 구분, FAQ·WebApplication·메인 JSON-LD의 설명 일치를 검사했다.

두 스크립트의 `node --check` 및 변경 파일 `git diff --check`도 통과했다.

## 남은 통합 확인

이 절은 최초 문구 검토 시점의 후속 목록이다. 이후 중앙 작업에서 홈 미니 카드/FEED 시각도 수정했고, 최종 브라우저·스냅샷 결과는 [통합 검수 보고서](../platform-review-remediation.md)의 C절과 로그를 기준으로 한다.

VM 검사는 DOM 레이아웃·실제 API 응답·지연된 전체 사이트 스크립트를 검증하지 않는다. 메인 `loadAll()` 이후 랜딩의 미니 카드 상태와 `FEED.meta.lastUpdated`가 원문 검증 시각으로 오해되지 않는지 통합 브라우저 검사에서 별도 확인한다. `home-sep20.js`의 기존 데이터 설치 함수가 링크 존재로 `hasOfficialNotice`를 설정하는 부분은 이번 문구 수정 범위에서 변경하지 않았다.

최종 브라우저 검사 후 정적 HTML 스냅샷을 다시 작성하고, 쓰기 없는 스냅샷 검사를 통과시켜 초기 HTML과 최종 요약의 차이를 없애야 한다. 이 문서는 그 브라우저 검사 또는 배포가 완료됐다는 증거가 아니다.
