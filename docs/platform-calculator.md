# 계산기·관심 노선 구현 기록

기존 정적 HTML 계산기와 항공사별 공시 배열, 노선 맵, 언어 선택, 목적지 자동완성, 제휴 링크를 유지했다. React·서버·회원가입·유료 서비스·새 패키지는 추가하지 않았다.

## 감사에서 확인한 문제

- 계산기 `updateResult()`는 선택한 노선이 없으면 첫 노선으로 대신 계산했다. 선택하지 않은 노선의 성공 결과를 만드는 이 동작을 제거했다. 검색창 입력과 선택 코드가 다를 때도 과거 선택값을 재사용하지 않는다.
- 기존 표는 고정 환율로 USD를 KRW로 바꾸어 항공사 간 최저액을 선택했다. 새 표는 원 공시 통화를 그대로 표시하고, 통화별 최저액을 별도로 계산한다. 내비게이션의 통화 선택이 공시액을 재산정하지 않는다.
- 월별 차액과 변동률 대신 ‘비교 월 최저 항공사 대비 차액’이 주요 결과였다. 기존 노선 검색 위에 발권월 입력과 항공사 필터를 추가해 실제 월별 차액을 표시한다.
- `OFFICIAL_ROUTE_MAP.BX`에 남은 과거 그룹을 그대로 사용하면 부산–나리타, 방콕, 괌, 시즈오카의 현재 공시 그룹이 잘못 선택된다. 10월 공식 원문과 11월 공시의 목적지 목록을 사용하도록 수정했다. 10월 원문: <https://www.airbusan.com/content/common/customercenter/noticeDetail?id=4407>. 부산–나리타는 10월 USD 37 → 11월 USD 43, 인천–나리타는 USD 66 → USD 77이다.
- 왕복 × 2에는 귀국편 공시 근거가 없다. ‘단순 왕복 추정’ 및 편도 × 2 × 인원 가정을 결과에 명시했다.
- 계산기 자체의 중복 제휴 이벤트 핸들러를 제거하고 공통 분석 모듈을 사용한다.
- 기존 ULN과 새로운 UBN은 별도 공항 코드로 유지한다. BX 부산–UBN만 항공사의 [2026년 9월 기준 국제선 공시운임표](https://www.airbusan.com/content/individual/booking/fareInternational)의 부산–울란바토르 출발지 근거와 [PUS–UBN 명시 공지](https://www.airbusan.com/content/common/customercenter/noticeDetail?id=3863)를 대조해 추가했다. 10월/11월 공식 노선군 3의 USD 78/90을 표시한다. 공시 금액의 적용 조회이며 현재 운항 일정·좌석 공급을 보장하지 않는다고 명시한다. CJU/ICN 출발, 다른 항공사의 UBN 노선, 마일리지는 추정하지 않았다.

## 파일과 역할

- `public/fuel-surcharge-calculator.html`: 기존 UI와 데이터 로더 유지, 월 입력/항공사 필터/관심 노선 영역, `AeroCalculatorBridge` 노선 상태 접근·복원, 유효하지 않은 첫 노선 대체 제거.
- `public/calculator-oct20.js`: 기존 10월 데이터와 원 출처 링크를 `AERO_CALCULATOR_OCTOBER`로 노출. 새 렌더러가 있으면 반복 보정 타이머를 중단한다.
- `public/calculator-platform-core.js`: 브라우저/Node 공용 비교·저장·검증 피드 변환·공식 노선군 조회 모듈. `officialRouteGroupIndex()`는 메인 조회에서도 사용할 수 있다.
- `public/calculator-platform.js`: 기존 데이터의 월별 조회, 원 통화 결과, 출처/발표일/원문 검증/수집 시각, 이벤트, 관심 노선·최근 검색 연결.
- `public/calculator-platform.css`: 기존 하늘색 디자인의 비교 표·모바일 카드 배치. 모바일에서도 발권월·원 통화·출처를 확인할 수 있다.
- `public/notice-group-source.js`: 별도 원문 확인으로 저장한 10월 BX 노선군 자료. 기존 공시 배열을 덮어쓰지 않는다.

## 비교 규칙과 데이터 한계

차액은 비교 월 − 기준 월, 변동률은 차액 / 기준 월 × 100이다. 기준액이 0이면 차액만 표시하고 변동률은 계산 불가로 안내한다. 항공사·출발지·도착지·부과 기준·통화·편도 조건이 모두 같아야 비교한다. 같은 달, 미확인 기록, 공시 없는 달은 비교하지 않는다. 미래 월은 이전 월이나 0원으로 대체하지 않는다.

기본은 2026-10과 2026-11이다. 다른 달을 입력할 수 있고, 기존 `MANUAL_OVERRIDES`에서 정확한 부과 기준과 원문 출처가 확인된 월만 조회한다. 예전 항공사별 거리 표기법이 다르면 임의로 구간을 변환하지 않고 데이터 없음으로 처리한다.

기존 10월 배열의 발표일·수집 시각·원문 검증 시각이 없는 항목은 ‘미기록’으로 표시한다. 공시 확인일과 적용월 시작일을 서로 대신 사용하지 않는다. 10월 ZE 원문 노선군을 재확인할 수 없어 기존 금액은 재검증 필요 상태로 보존하고 월별 증감 계산과 공식 업데이트 배지에서는 제외한다. 11월 YP는 공식 공시 확인 대기 상태이며 10월 금액을 재사용하지 않는다.

새 `official_surcharge_feed.json`도 읽는다. 해당 피드의 `item.metadata`에 항공사·출발 공항·도착 공항·부과 기준·통화·편도 조건이 명시되고, `dataStatus=confirmed`, `validationStatus=passed`, 검사·수집 시각, 공식 HTTPS 출처, 일치하는 적용월/금액이 있어야 사용한다. 항공사·노선·월·편도 조건이 같은 유일한 신규 레코드를 기존 배열보다 먼저 선택하며, 신규 통화·부과 기준은 그대로 표시한다. 이전 월과 조건이 다르면 비교를 거부한다. 누락값을 상위 기본값이나 거리 추정으로 채우지 않는다. 중복·모호한 신규 기록이 있으면 금액을 표시하지 않고 이전 내장 공시로 대체하지 않는다. 피드 자체를 읽을 수 없거나 해당 조건의 신규 레코드가 없을 때만 내장 공시를 보존한다.

데이터 형식 검증과 원문 확인은 다르다. `validatedAt`을 원문 검증 시각처럼 표시하지 않는다. 새 피드의 `sourceVerificationStatus`가 확인 상태여야 공식 업데이트 배지에 포함하고, 원문 확인 시각은 `sourceVerifiedAt`만 사용한다.

## 관심 노선과 이벤트

`localStorage` 키는 `aero.calculator.v1`이다. 최대 20개 출발지·목적지·항공사 조합과 비교월, 인원, 편도/추정 왕복 조건을 저장한다. 동일 조합 저장은 갱신이며, 조회·삭제·최근 검색 자동 복원 및 수동 복원을 지원한다. 저장소 차단·용량 오류·손상 JSON은 계산기를 중단시키지 않는다. 저장 불가 시 현재 화면에만 유지된다는 안내를 표시한다. 원문 입력이나 이메일은 저장하지 않는다.

저장 시 확인한 공식 레코드의 금액·통화·부과 기준 스냅샷을 다음 방문 기록과 비교한다. 원문 URL만 바뀌는 링크 수정은 공식 공시 수정 배지를 만들지 않으며, 예전 URL 포함 스냅샷도 호환한다. 새 공식 공시, 공식 수정, 과거 공시 추가/수정을 구분한다. 전망·미확인·기존 검증 미기록 자료는 배지를 만들지 않는다. 처음 저장할 때 공식 공시가 없었던 `{}` 기준도 이후 공식 발표를 감지할 수 있다. 저장 노선을 열면 변경을 확인한 것으로 기록한다. 백그라운드 푸시나 이메일 발송 기능은 아니다.

계산 버튼을 눌렀을 때 `route_search`를 보내고, 동기 렌더링이 끝난 실제 결과에 `route_result_view` 또는 `route_no_result`를 보낸다. 복수 항공사 결과에는 `airline_compare`, 유효한 월 비교에만 `month_compare`를 보낸다. 사용자가 발권월 입력을 변경해 유효한 비교가 표시되는 경우에도 `month_compare`만 한 번 보낸다. 동일 값의 중복 change와 초기 표시, 데이터 수신, 언어 변경, 최근 검색 복원, 재렌더링은 새 이벤트로 집계하지 않는다. `AeroAnalytics.track()`의 동의·중복·파라미터 필터를 재사용한다. 이메일 신청 기능과 `alert_subscribe`는 추가하지 않았다.

## 검증

- `node --test tests/calculator.test.cjs`: 10개 테스트 통과. native 차액·변동률/0원, 통화·항공사·구간 불일치 거부, BX/ZE 원문 노선군, 저장·복원·삭제·차단 저장소, 공식/과거/전망 배지 구분, URL 수정 시 배지 방지, 원문 확인 공시의 최저액, 신규 통화·기준 수신 및 중복 시 이전값 대체 차단, 원문 확인과 형식 검사 구분을 검사한다.
- `node scripts/verify_calculator_platform.cjs`: 기존 Playwright로 별도 로컬 서버를 열어 실제 검색 UI, KE 공식액/월차, BX 원문 노선군, 공시 없는 YP/미래월, 저장·복원·삭제·변경 확인, 이벤트 중복, 모바일 너비, 차단 저장소, 검증 피드 연결을 검사한다. 외부 네트워크 요청을 차단한다. 스크린샷은 `tmp/platform-verification/calculator-comparison-mobile.png`에 저장한다. 실행 결과는 통합 작업의 최종 보고에 기록한다.

새 UI 문구는 한국어와 영어를 제공하고, 기존 일본어·중국어·프랑스어·독일어 선택에서는 새 항목에 영어를 사용한다. 기존 번역된 공항명·항공사명·탐색 UI는 유지한다. 나머지 신규 UI 번역은 별도 번역 검토가 필요하다.

## 이메일 알림 후속 설계

현재는 계정/발송 백엔드를 추가하지 않았다. 도입 전에 구독 의사 이중 확인, 최소 수집 항목·보관/파기 기간, 빈도 제한, 봇·스팸 방지, 서명된 수신 해지 링크, 실패/반송·발송 로그, 공식 신규 공시 승인 후에만 발송하는 조건을 설계해야 한다. 발송 서비스 요금은 예상 구독 수·월 발송량과 실제 공급자 견적으로 판단한다. 작동하지 않는 신청 UI나 비용 추정값을 운영 기능으로 표시하지 않는다.
