## 재현 가능한 근거

- `docs/review-evidence/source-reconciliation.json`: 11개 항공사·월별 사실 스냅샷, 전체 구간·금액·노선군, 원문 URL, 검토 방식, 발표일/적용기간, PDF SHA256 및 확인 페이지.
- `docs/review-evidence/official-web-recheck.json`: KE/TW 공식 도메인 본문 접근 및 직접 접속 제한 기록. 원본 HTML을 재구성한 파일이 아니라 사실 추출 기록이다.
- 저장 PDF 위치는 프로젝트 상위 작업공간의 `유류할증료/2026.11 유류할증료/` 및 `유류할증료/2026.10 유류할증료/`. 원본을 웹 공개 폴더로 복사하지 않았다.
- 임시 시각 확인물은 `artifacts/source-review-20261021/`. 이 디렉터리의 렌더링·작업 스크립트는 배포 대상이 아니다.
- 보관된 PDF의 출력 시각, 공시 발표일, 이번 검토 시각을 혼동하지 않는다. 7C는11월 제목 및 발권일 기준을 확인했지만 별도 공시 시작/종료일 줄은 없는 저장 페이지이므로 월 적용 표현을 근거로 한다.

## 구현과 상태 모델

`public/source-provenance.js`는 독립된 검토 스냅샷을 동결한다. 런타임의 `official_verified`, `confirmed`, 파서 confidence, URL 호스트, HTTP 성공만으로 확정 상태가 되지 않는다.

- `evaluate(record)`: 항공사·적용월·공시 원문 식별자·통화·방향·출발국·원문 구간·인덱스·금액의 정확한 일치를 요구한다. ZE는 원문 노선군 내 정확한 출도착 조합, BX는 출발지를 포함한 노선군 조건도 확인한다.
- `evaluateNotice(record)`: 전체 공시 표의 특정 구간 금액 검증. 노선 선택 없이 해당 구간 자체를 대조한다.
- `getNotice(airline,month)`: 변경 불가능한 검토 메타데이터 조회. 기존 금액을 자동 덮어쓰는 함수가 아니다.
- `summarize(notices,month)`: 전체 금액/구간/노선군/기간이 맞아야 해당 공시를 검증 완료 수에 포함한다. null은 공시액 부재로 유지한다.
- `_shared.js`의 공통 공시 문구와 상태는 이 집계로 계산한다. 공식 웹 또는 저장PDF라는 근거 유형을 설명하며 실시간 웹 성공을 주장하지 않는다.
- `market-oct17.js`의 뉴스 카드 `reportedDate`/`eventDate`는 검토된 발표일만 사용한다. KE/LJ/BX의 미확인 발표일은 null이고 본문에 언어별로 미확인을 표시한다. 기존 사이트 카드 게시/갱신 시각과 별도 `sourceVerifiedAt`을 유지한다. 6개 언어의 제목·상태·FAQ·확인 항공사 목록도 원문 검증 집계에서 계산한다.

`lib/validation/provenance.js`와 파이프라인은 기술 검사 통과를 `TECHNICAL_PASS / SOURCE_HOLD`와 구분한다. 검토 기록과 일치하지 않는 후보는 `buildProposal`에서 보류하고 공개 피드 전체를 유지한다. 직접 `mergeFeed` 호출과 게시 직전 `validateChanges`도 같은 원문 검증을 적용한다. `sourceBand`, `bandIndex`는 명시된 값만 정규화하며 과거 레코드에서 추정하지 않는다. 원문 검토 없는 미래 후보의 자동 확정 게시는 의도적으로 불가능하다. 검토 기록 추가 후 다시 실행해야 한다.

새 검토 대상을 승인하려면 원문 금액과 실제 부과 조건을 확인하고, 별도 근거 기록 및 스냅샷을 변경 검토에 포함한다. 사이트 배열에서 스냅샷을 자동 재생성하는 작업은 제공하지 않는다. CI는 11월 공통 선언과 명시적10월 노선군을 스냅샷에 대조하고, 새 수동JSON/피드 변경도 원문 미검증이면 거부한다.

## 과거 데이터 및 제한

기존 수치와 원래 상태 표시는 원본 기록으로 보존한다. 메타데이터가 불충분하거나 원문 스냅샷이 없는 과거 항목은 최신 확정 비교·최저액·신규 공시 배지의 근거가 될 수 없다. 이는 데이터가 틀렸다는 결론이 아니라 재검증 범위의 제한이다. 전체 과거자료를 임의로 확정하거나 일괄 삭제하지 않는다. 구간 경계가 달라 보이는 과거 라벨을 임의의 거리 경계로 맞추지 않는다.

새 라이브 수집기의 출력에는 검토 스냅샷에 필요한 원문 구간·방향·출발국 등이 없을 수 있다. 이 경우 기술 검사가 통과해도 게시를 보류한다. 전체 자동화 완료를 의미하지 않는다. 후속 자동 대조에는 수집 원문과 파서 추출값을 검증하는 항공사별 독립 파서 또는 사람의 원문 검토 절차가 필요하다.

`.env.local` 및 기존 Anthropic/환율 설정 존재 여부는 boolean으로만 확인했고 값은 출력하지 않았다. 실운영 수집 검증은 루트 작업에서 별도로 실행·기록하며 이 문서의 원문검증과 구분한다.

루트가 실행한 KE/LJ/7C 실제 dry-run은 HOLD였다. KE timeout, LJ 수집 경로 실패, 7C HTTP403 및 Anthropic HTTP400 잔액 부족이 기록되었고 공개 JSON 해시는 모두 유지되었다. 실제 결과는 `docs/review-evidence/live-pipeline.log`와 `live-pipeline.json`에 그대로 보존한다. 이 결과를 이후 코드 수정으로 성공 처리하지 않는다.

해당 실측에서 발견된 추가 낭비를 수정했다. 기존 AI 검색 복구는 먼저 수행하되, 복구 후에도 fallback·오류 상태이거나 본문이 비었거나 공식 URL이 잘못된 수집 결과는 유료 파서 호출 전에 제외한다. 보고서에 `parserSkipped`/`SOURCE_HOLD` 사유를 남기고, 파싱이 빠진 항공사가 있는 배치는 게시하지 않는다. 성공한 AI 검색 복구와 정상 공식 본문은 기존 파서를 유지한다. 이 수정 후 유료 API/실네트워크 재실행이나 충전은 하지 않았고, 주입된 파서 함수로 fallback 호출 횟수0·정상 본문만 전달·전체배치 보류를 확인하는 회귀3개가 통과했다.

## 테스트

- 원문 바인딩 회귀: 전 구간 대조, +1 금액 변조, 통화·월·원문ID·방향·출발국·구간·인덱스 변경, 과거 metadata 누락, null/0 구분, ZE/BX 노선군, 전체공시집계, 근거스냅샷 불변성.
- 뉴스 원문 메타데이터 회귀 3개: 발표일 null/확인일 구분, 6개 언어 집계와 이전 10월16일 고정 문구 제거, 미검증 금액 보존 및 확정 목록 제외. source-provenance 테스트9개와 함께12개 통과.
- 파이프라인 회귀: 기술통과/파서검증문자열만 있는 후보 보류, 직접 병합 우회 차단, 게시직전 금액 변경 거부, 실제 검토된 LJ금액 후보의 임시 피드 게시와 백업.
- 데이터/원문 테스트는 로컬 Node 기본 테스트 도구로 실행. 임시파일 atomic rename 성공 테스트는 Windows sandbox의 알려진 EPERM으로 제한되어 루트 작업에서 중앙 재실행한다. 나머지 실패를 숨기지 않으며 최종 통과 수는 중앙 결과를 따른다.

새 패키지, 서버, 유료 서비스는 추가하지 않았다.
