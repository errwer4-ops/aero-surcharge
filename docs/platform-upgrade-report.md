# Aero Surcharge 플랫폼 고도화 결과

기준일: 2026-10-21 KST. 작업 저장소: `aero-v37-fixed/aero-v36`, 시작 커밋 `975b7e8`.
로컬 코드와 테스트에 적용했다. 프로덕션 배포, 외부 계정 변경, 유료 자원 생성, 운영 데이터 삭제는 실행하지 않았다.

## A. 기존 사이트 분석

현재 기술은 정적 HTML/CSS/JavaScript, Node.js CommonJS, 기존 Playwright 수집기, JSON 데이터, Vercel 배포 설정, MyRealTrip API 중계다. 기존 GA4 ID와 AdSense 게시자 ID가 있었고 Clarity ID·이메일 발송 시스템은 확인되지 않았다. React·Next.js·DB로 전환하지 않았다.

| 기존 기능 | 감사 분류와 결과 |
| --- | --- |
| 노선·항공사 조회, 다국어, 공식 원문 링크 | 정상 기능 재사용. 검색어를 수정해도 이전 공항이 선택되는 오류는 재현 후 수정 |
| 계산기와 월별 공시 배열 | 기존 검색·배열 재사용. 같은 통화·부과 기준의 임의 두 발권월 비교로 확장 |
| 뉴스·전망 | 페이지 유지. 공통 렌더러의 중복 제목과 초기 HTML의 오래된 월 문구 수정. 모든 과거 기사·시장 수치의 사실 검증까지 완료한 것은 아님 |

| 관심 노선 | 신규 구현: 기기 내 저장·복원·삭제와 공식 데이터 변경 표시 |

실제 재현한 주요 오류는 수집 결과와 항공사의 배열 순서 연결, mock 파싱값의 게시 가능 경로, 실패·누락·0원·급변 방어 부족, dry-run의 공개 로그 수정, KST 월 계산의 중복 시간대 적용, 계산기의 첫 노선 대체, 고정 환율을 통한 서로 다른 통화의 최저액 비교, BX의 오래된 노선군 매핑, 초기 HTML/최종 DOM의 월·제목 차이, 항공사 인덱스 H1 누락이다.

데이터는 한 JSON만 사용하지 않고 `_shared.js`, 수동 override, 페이지별 월 배열에도 분산돼 있었다. 기존 호환성을 위해 이 구조를 보존하고 검증 어댑터를 추가했다. 과거 피드 51구간의 메타데이터 경고 111개, 수동 JSON의 경고 319개를 임의 값으로 채우지 않았다.

공식 원문 대조 결과와 링크는 [출처 검토](platform-sources-seo-business.md)에 기록했다. KE·RS의 10/11월, BX의 10/11월, OZ·TW의 11월 수치를 대조했다. 7C 11월은 제목·발표일만 확인됐고 금액표 추출에 실패했다. LJ·ZE 11월 원문은 이번 웹 접근으로 재검증하지 못했다. 접근 실패를 기존 데이터 오류로 단정하지 않았다.

BX 부산–UBN은 공항 운영자와 에어부산 공식 노선 자료를 확인해 추가했다. ULN과 자동 치환하지 않고 ICN/CJU 출발을 추정하지 않는다. 공시 적용 조회는 실시간 운항 일정·좌석 판매를 보장하지 않는다.

비교 금액이 없으면 과거값이나 0원으로 대신하지 않는다. 기준액 0원은 변동률 계산 불가, 서로 다른 통화·부과 기준은 비교 불가다. 새 검증 피드에 실제로 통화/기준이 바뀐 항목이 있으면 해당 항목을 표시하고 이전 내장값으로 숨기지 않는다. 중복·모호한 후보도 이전 금액으로 대체하지 않는다. 기술 검증 통과와 원문 확인 상태를 구분한다.

기존 데이터 파일·URL·수집기·파서·검색 입력·다국어 탐색·제휴/API를 유지했다. `public/data` 변경은 없다. 새 비교 UI 문구는 한국어/영어이고 나머지 언어는 신규 문구에 영어 대체를 사용한다.

브라우저 검사는 실제 Chromium과 기존 Playwright를 사용한다. 외부 추적·광고·제휴 API 요청은 차단하며, 테스트용 후보 데이터는 브라우저 응답에만 주입한다. 테스트의 가상 금액/미래 공시는 서비스 파일에 기록하지 않는다. 공식 수치·월차·통화 불일치·공시 없음·관심 노선 수명주기·저장소 차단·이벤트 중복·모바일 너비·초기 HTML 일관성을 검사한다.

실행 증거는 `tmp/platform-verification/verification.json`과 같은 폴더의 모바일 화면 파일에 있다. 계산기 모바일 전체 화면을 육안 확인했으며, 자동 너비 검사와 함께 결과 카드·월 입력·저장 영역의 배치를 확인했다. 이 임시 증거 폴더는 Git에 포함하지 않고 테스트로 다시 생성할 수 있다.

처음 게시 안전성 테스트의 파일 교체와 제휴 모의 서버 연결이 샌드박스 제약으로 실패했으며, 같은 테스트를 허용된 환경에서 재실행해 통과했다. 실패를 코드 성공으로 간주하지 않았다.

미검증: 실제 운영 GA4 DebugView 수신, Clarity 세션 수집, 광고 심사/노출/수익, 제휴 판매·환불·수수료, 실제 인증정보로 전체 항공사 수집·LLM 파싱, 배포 환경 및 외부 GitHub Actions 실행, 모든 과거 기사와 전체 노선의 원문 대조, 실측 Core Web Vitals. 로컬 통과는 이 항목들의 성공을 뜻하지 않는다.

## D. 보류된 작업

- **운영 배포:** 수행하지 않음. 이 변경을 검토한 뒤 기존 배포 절차에서 처리해야 한다.
- **Clarity:** 실제 프로젝트 ID가 없어 설정값은 빈 문자열이다. 마스킹·동의·운영 확인 후 실제 ID를 설정해야 한다.
- **광고:** 로컬 변경의 `adsEnabled` 기본값은 `false`다. 기존 게시자 ID는 유지했다. 운영 대상 지역과 CMP 요건을 확인한 뒤 활성화해야 한다. 이 설정 상태로 배포하면 광고 스크립트는 로드되지 않는다. 자체 동의 UI가 인증 CMP를 대체한다고 주장하지 않는다.
- **분석 운영:** GA4 기존 ID를 재사용했으나 DebugView/관리자 설정은 계정에서 확인해야 한다. 절차는 [분석 운영 문서](platform-analytics.md)에 있다.
- **데이터 보완:** 과거 발표일·수집일·적용일·출처 누락, LJ/7C/ZE 웹 원문 재검증, ZE 10월 노선군 확인. 확인 전 비교/알림 근거를 만들어 채우지 않는다.
- **SEO:** 기존 `.html` canonical과 Vercel cleanUrls 리디렉션의 운영 URL 통일 검토. 검색 노출·AI 답변 노출 효과는 확인하지 못했다.
- **이메일·SaaS:** 수신 동의/해지/발송 시스템, 재배포 권한, 고객 수요, 사용량 기반 실제 공급자 비용 확인이 선행이다. 미리 서비스나 결제를 활성화하지 않았다.

## E. 성능 및 유지관리

새 패키지·DB·유료 자원은 없다. 기존 Playwright와 Node 내장 test/VM/fs를 사용한다. Node 요구 버전은 기존 의존성과 맞춰 20 이상, CI는 22다. 새로운 사용자 입력/결과/저장은 클라이언트에서 동작하며 별도 서버 왕복이 필요 없다. 기존 반복 결과 보정 타이머를 새 계산기 사용 시 중단했다. GA4/Clarity는 동의 이후 비동기로 로드한다.

성능 향상 수치나 운영 속도를 측정했다고 주장하지 않는다. 공통 분석과 비교 모듈만 추가했고, 큰 `_shared.js`와 월별 누적 스크립트의 전면 리팩터링은 하지 않았다. 정적 스냅샷으로 초기 HTML 정보량이 늘며, 공시 변경 시 스냅샷 갱신도 필요하다.

유지관리 순서:

1. 공식 원문 수집 및 출처/방향/통화/적용 기간 확인.
2. 후보 및 기존 대비 변경 검증. 실패·급변은 공개 전 오류 로그로 검토.
3. 기존 정상 데이터 백업, 동시 수정 확인, 통과한 전체 후보만 게시.
4. `npm test`, `npm run validate:data:changes`, `npm run validate:service-data`.
5. 렌더러/데이터 변경 후 `node scripts/sync_static_snapshots.cjs --write`, `npm run test:seo`.
6. `npm run test:static`, `npm run test:platform`, `npm run test:calculator`, `npm run test:myrealtrip`.

같은 검사를 GitHub Actions에 연결했다. 실연결 출처 검사는 `--check-links`로 별도 실행 가능하다. URL이 열린다는 사실만으로 금액의 정확성을 증명하지 않는다. 백업과 검토 로그는 공개 디렉터리 밖 `artifacts/data-validation/`에 남으며 자동 삭제하지 않는다.

## F. 완료 요약

- **구현 완료:** 수집 실패/오류 게시 차단, 하위 호환 정규화·검증, 로컬/CI 검사, 월별 원 통화 비교, 단순 왕복 표시, 관심 노선·최근 검색·공식 변경 배지, 동의 기반 GA4 이벤트, 정적 HTML/메타 동기화, 제휴 클릭 분석, SaaS/이메일 검토 보고서.
- **일부 구현/운영 확인 필요:** Clarity 실제 연결, 광고 재활성화, 과거 데이터 메타데이터 보완·전체 원문 대조, 신규 UI의 추가 4개 언어 번역, 검색·분석·수익 성과 확인.
- **미구현:** 이메일 발송, 사용자 계정, 유료 API·결제/구독. 기반 시스템·수요·권리 확인이 필요하다는 요청에 따라 선행 개발하지 않았다.
- **현 단계에서 불필요:** 프레임워크 전환, 새 DB, 비슷한 SEO 페이지 대량 생성, 추가 광고 슬롯, 검증되지 않은 전망/가격/수익 생성.
